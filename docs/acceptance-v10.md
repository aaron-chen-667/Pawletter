# Pawletter v10 验收清单（2026-10-22）

本清单区分实际服务验收、浏览器模拟接口验收和尚未完成的能力，避免把页面可点击当成后端已接通。

## 本轮用户反馈与落实

| 用户反馈 | 实现与验收 |
| --- | --- |
| 真实新用户注册，移除测试身份/环境 | 正式用户名密码注册，服务端保存账号与生活画像；默认实名待核验。旧本地演示身份不迁移为真实身份。 |
| 先浏览，高频操作再引导注册 | 首页可匿名查看公开档案；喜欢、聊天、申请等动作弹窗，点击前往注册后进入流程。 |
| 明确下一步为语音访谈 | 按钮为“同意公约，进入下一步语音访谈”。 |
| 访谈像 Agent 聊天，减少填表 | 单一聊天区域；按住录音、松手发送、上滑取消；文字作为备用；AI 理解回答，最后统一确认画像。 |
| 自动转写失败 | 连接真实 ASR；限流显示服务繁忙，保留录音并可重试。未识别内容不冒充事实。 |
| 生活画像称号、聚合分析与推荐理由 | 服务端 AI 生成生活名片：称号、摘要、要点、宠物类型、依据和未知项；错误可重新整理，不伪造成功。 |
| 申请不要重复填写生活画像 | 复用注册画像，一段语音/文字补充，预览本次分享内容后明确确认提交。申请与站点审核均使用真实 API。 |
| 主动招呼默认开启 | 新账号默认开启，注册前说明，可主动关闭；保留已有关闭状态。 |
| 喜欢的独立入口 | 附近／随缘遇见／喜欢的三段导航；喜欢的为信息列表和回看入口，不滑卡。 |
| 场景文案与装饰过大、筛选挤 | 场景标题缩小为短横幅，保留小图标；筛选前后留白；390×844 与 360×640 滑卡操作不被导航遮挡。 |
| 救助站入口场景 | 从宠物卡与详情进入对应照护站点；“我的”有认识救助站入口；发现页删除额外站点横条。 |
| 角色切换、删除重复登录横幅 | 默认领养者；我的页角色菜单进入救助站登录，按服务器角色鉴权。 |
| 成功领养宠物显示在主人旁，点击聊天 | 仅服务端已完成且归属当前用户的领养关系投影出宠物头像，居中排列，可打开该宠物 AI 分身。 |
| 个人公开主页显示成功领养宠物 | 基于当前用户服务端领养关系显示，不混入他人的宠物或私人联系信息。 |
| 退出登录位置与二次确认 | 移到我的页面底部，二次确认后撤销服务端会话、清空当前显示并回到游客界面。 |
| 宠物消息以独特第一视角表达 | 救助站维护表达偏好；聊天与申请阶段通知均用宠物第一视角，不能把待审核说成通过。 |
| 救助站补充信息最短路径 | 工作台首屏“给宠物补充”直接打开录音页，选宠物后长按录音，自动归档；无需人工分类填写。 |
| 长期资料成为对应宠物 AI 的记忆 | 每只宠物独立 agent 配置和资料；基本档案＋救助者有效长期记录是唯一事实来源。聊天不能写入宠物资料。 |
| 各级页面按钮视觉优先级 | 统一主操作、次操作、安静导航、危险操作、禁用与焦点样式；覆盖主 tab、注册、个人资料、申请、对话、站点和弹窗。 |
| 详情右上改分享，喜欢移到照片右下 | 分享优先系统分享，降级复制链接/可选取链接；分享链接仅携带宠物 ID；取消系统分享不自动复制。 |

## 验证证据

- 前端 38 项自动化测试通过；后端核心集成测试覆盖真实 PostgreSQL 语义（PGlite）。AI、存储的单元测试使用替身，不与真实联调混淆。
- 浏览器脚本 `frontend/tests/v10-ui.mjs` 使用隔离接口夹具，验证 33 个页面状态、两种手机尺寸、无水平溢出和无页面异常，并检查小屏滑卡按钮、退出位置和分享直达。图片保存在开发机 `.preview/v10/`，不提交照片或运行态数据。
- 正式接口脚本 `backend/scripts/verify-agent-loop-live.js` 已通过：创建内部宠物 → 从档案建立分身 → 修改表达设定 → 合成中文录音上传转写 → 自动写入资料库 → 领养者获得引用回答 → 救助者更正“小球”后回答变化 → 撤回后不再引用。
- 同一正式脚本验证真实申请、站点审核、第一人称通知与待核验阻止最终交接。验收后撤回申请、撤回验收资料、下架内部宠物并注销会话，不放入公开列表。
- 正式注册/登录/资料读取/退出撤销已经通过。最终修订 `pawletter-api-00010-jsg` 的访谈、生活画像与 ASR 均为 200，注册为 201。上游曾出现 ASR 429 和画像结构不合格；这些失败不会产生虚假成功状态。最终结果见发布记录。

## 必须保留的边界与后续事项

1. 短信与实名认证服务尚未开通（用户已确认）。当前是真实账号，手机号/姓名是用户填写资料，不代表核验；申请可送达救助站，但核验前不能完成交接。
2. 实时字幕依赖浏览器 SpeechRecognition；不支持时明确显示“正在录音，松手后转写”。最终转写走服务器 ASR。真实手机麦克风、系统授权和噪声环境仍需用户设备验收；不能把桌面合成录音当成真机结果。
3. 上游模型与语音服务仍可能限流；保留内容、明确失败与重试，不使用预设回答冒充 AI 成功。
4. 完整自动回访、评分、媒体上传与公开动态的服务端闭环尚未完成。旧原型相关纯本地模块不等于正式服务；不应对外宣称已完成自动回访或真实评分。
5. 喜欢、浏览进度与领养者偏好记忆目前保存在当前浏览器会话中；账号、已确认生活画像、申请、宠物档案与宠物问答保存在服务器。跨设备收藏同步仍待接入。
6. 宠物创建支持名字、物种、文字基础介绍与语音资料；照片/视频上传及自动从图片建档仍待接入。公开目录仅展示救助站实际发布的资料，不继续填充旧演示宠物。
7. 本轮不创建新的 API Key 或改变供应商计费计划，使用既有服务端秘密配置；任何密钥、密码、录音和私人申请资料均不提交 Git。
