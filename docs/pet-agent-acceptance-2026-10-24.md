# 宠物 AI 分身正式服务验收 · 2026-10-24

## 结果

正式 API 的 17 只公开示例宠物逐只通过本轮验收。每只均读取自己的救助档案、有效共享资料和独立表达配置；以第一人称回答，引用本宠物来源，未知生日与母亲名字不编造，领养者聊天不写入宠物事实库。

这次验证的是正式后端和真实模型响应，不是浏览器示例预设回答。示例档案仍明确标注为虚构观察，不代表照片中动物的真实经历。用户自己的救助站没有被这些测试数据填充。

## 创建与记忆更新闭环

使用两个内部测试宠物、QA 救助者和 QA 领养者，真实调用创建、归档、聊天、更正、风格修改及撤回接口，9 项通过：

1. 新建时没有玩具资料，不给玩具事实引用。
2. 救助者记录连续观察到喜欢蓝色小球，回答引用该记录。
3. 私密的紫色布包记录不进入领养者可见知识及回答。
4. 第二只宠物回答自己的黄色毛线球，不引用第一只的资料。
5. 提交更正后，旧观察立即退出有效知识。
6. 新记录归档后，回答变为红色布老鼠，引用更正后的记录。
7. 救助者修改为安静、简短的两句表达，配置 revision 增加，事实仍是红色布老鼠。
8. 撤回更正记录后，下一次回答为“我不知道自己最喜欢什么玩具，档案里没有记录过”，没有引用，也没有复用旧聊天中的玩具事实。
9. 内部测试宠物不进入公开目录；结束后测试记录撤回、宠物取消公开、测试会话退出，清理完成。

基础档案与长期资料会用于每次回答。已撤回、被更正、非共享的记录不会作为当前事实；推理期间发生撤回也有服务端检查。历史聊天保留为会话记录，不转成未经救助者确认的宠物记忆。

## 本轮发现与修正

发现示例原始照护要求“能接受持续的日常练习”省略了主语，模型可能解释成宠物已经具备的能力。已同时修正服务端指令与来源：

- 明确照护要求、未来家庭期待不等于当前已经发生的行为或能力；性格描述不得自行扩写成额外动作。
- 17 条原示例照护记录通过更正形成新记录，明确“对未来领养家庭的照护要求”，保留原记录和更正关系。只匹配原始示例文本，跳过人工修改、私密或撤回记录；重复执行不重复更正。
- 正式接口复核全部 17 只：新来源有效，旧来源不再返回。
- 再实际询问曲奇、可乐、年糕，三者均能区分已有习惯与未来家庭要求，引用当前有效来源。

例如曲奇更正后回答：“希望带我出门时能够全程使用牵引绳，并且愿意接纳并陪伴我开展持续的日常练习。”可乐说明规律遛狗及牵引礼仪练习是未来家人的照护与训练陪伴，并非已经掌握的能力。
