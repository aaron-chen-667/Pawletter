# 救助站建档与补充 Agent 接口验收

本轮处理“录入新伙伴”和“补充”缺少 AI Agent 解析/连续对话的问题。它不是全部产品需求已完成的声明；其他缺口仍见 [main 走查](main-integration-audit-2026-10-24.md) 与 [修复清单](main-recovery-2026-10-24.md)。

## 查明的问题与改动

- 新伙伴已有 `POST /v1/intake/analyze` 多模态解析与维度追问，但前端承接语是固定拼接。本次新增服务端 `reply`，页面显示真实 AI 回应，再显示校验后的 `nextQuestion`。人工确认字段、明确纠正、跳过未知项的规则保持有效。
- 补充原来只有确认后提交 observation、异步抽取归档，录入阶段确实没有 Agent 对话。本次新增 `POST /v1/pets/:id/observations/analyze`，并接到正式页面“发送”。
- 补充分析读取当前宠物档案、最近 30 条有效资料、最多 6 轮前文，以及当前照片/视频抽帧和观察日期。仅负责该宠物的救助站可调用，跨站只读权限不授予分析权限。
- Agent 返回回应和必要的一个追问。仅确认入档才调用原有 observation 提交接口；Agent 回复不写入事实库，归档继续从用户原文选句，保留否定和不确定性。
- 分析失败保留原文和素材，可重新解析；编辑或移除前文会使受影响的后续分析失效，确认前重新解析。保存沿用原有幂等机制。
- `examples=1` 仍为本地预设演示，两个入口都明确显示“不调用真实 AI”。真实服务入口为 [救助站正式登录](https://pawletter-adoption-h5.chenaaron668.chatgpt.site/?mode=online&role=station)。

## 接口契约

`POST /v1/pets/:id/observations/analyze`，Bearer 救助站会话：

```json
{
  "text": "今天食欲比昨天少，原因还不清楚。",
  "images": [],
  "history": [{"text": "最近食欲变化。", "question": "什么时候观察到的？"}],
  "observedOn": "2026-10-25"
}
```

返回 `{reply, nextQuestion}`。`images` 最多 5 张规范 JPEG（`kind` 为 photo/video），视频由前端抽帧。文字最多 12000 字，前文与本轮总计最多 24000 字；`history` 最多 6 轮。更正已有记录可传 `replacesId`，服务端只读取同一宠物有效原记录。无 observation、knowledge、媒体写入，预算计数除外。错误明确返回 400/401/403/409/429/502，不回退为假 AI 成功结果。
