# 爪爪来信 · 公益领养 H5 Demo

独立的移动端 H5，不依赖父目录素材管理系统。运行时无第三方 JavaScript 依赖；jsdom 仅用于开发测试。

## 云端账号与真实 AI 链路

打开 `?mode=online`，或从“我的”及救助站工作台的线上登录入口进入。使用管理员开通的站点或领养者账号登录，角色由服务端决定。页面刷新后需重新登录；凭据和 token 不写入 localStorage，原有演示记录不会上传。

- 救助站：宠物列表 → 给宠物补充 → 选择宠物 → 按住说话 → 松开自动保存 → 后台转写、分类、归档；页面显示 queued / processing / archived / failed 状态并轮询。
- 录入时明确选择是否让 Agent 引用结果，关闭时仅本站可见。原始录音始终不向领养者开放。
- 网络重试保持原宠物、原内容和同一 Idempotency-Key；已完成上传的录音不会再次上传。服务端确认前不会显示为已归档。
- 更正立即使旧内容退出知识库，撤回后新的问答不再引用旧资料。
- 领养者：查看已发布宠物 → 与 Agent 聊天 → 查看引用的原文、站点和时间。资料不足时不编造回答。
- 建立新档案当前只支持名字、物种与介绍，再通过语音补充。照片视频、实名注册、申请、回访、评价等业务尚未接入这一线上模式。

API 固定为 `https://pawletter-api-446222711695.asia-east1.run.app`，AI Key 只在服务器端。`dist/pawletter-api.js` 来自统一仓库 `backend/client/pawletter-api.js`，修改时同步两份。真实 API 的 CORS 目前仅允许正式 H5 域名，因此 localhost 只用于界面检查；真实登录请使用正式网址。

本轮增加线上提交重试与 DOM 交互测试，`npm ci && npm run check && npm test` 可运行。浏览器自动化工具当前不可用，未完成新界面的视觉 QA 和手机真机麦克风验收。下文描述的是原有本地体验模式，不能用来判断云端业务已全部实现。

## 本地体验模式

- 首次打开直接展示领养者与救助站业务数据，主页面不再依赖“进入故事”按钮。既有申请、账号与编辑记录不会被覆盖。旧故事链接继续可用，切换场景入口保留在设置中。
- 申请详情可进入对应领养者主页；主页按正在申请、历史领养及每次站点评价、授权日常展示。南南有申请吐司及从小院领养糯米的完整记录。跨站仅展示公开信息，不开放其他站点的私密申请、回访或评价依据。
- 跟进卡片绑定领养人，提供主页、回访记录和主动回访入口。可指定照片、视频、语音及期望反馈时间；用户在消息页收到站内邀请，回复关联原请求，站点查看后仍需人工回复。未接入外部通知。
- 申请支持手机号、微信、邮箱，至少提供一种。提交前核对生活画像、偏好、照护条件与已保存语音；按提交时的快照展示给负责站点，不在公共主页公开。
- 新用户先确认公约，再完成四步语音或文字访谈，最后确认画像才创建账号并绑定身份；中途保存的是注册草稿，刷新可继续。访谈了解上班与离家时间、作息、可用照护时间、相处预期。“我的”入口优先展示已确认资料，通过“重新对话修改”更新；修改草稿不影响已确认画像和历史申请。
- 救助站工作台按申请、回访、档案、评价呈现可直接处理的待办。动物列表支持名字搜索和状态筛选，每张卡片可直接语音补充；宠物管理首页展示档案与资料库，表达设置成为次级入口。跟进优先展示未处理反馈，历史回复可折叠。
- 宠物补充链路：工作台直接进入语音页 → 选择宠物（从宠物卡进入则自动选好）→ 长按录音、松开自动归档 → 原页展示归档结果。录音期间锁定宠物，无分类表单和额外确认页。文字由规则自动分组，并标记长期/本次观察/待核实；保留记录日期、站点及原话时间描述。更正或撤回一条记录后，旧内容保留历史但不再被 Agent 引用。
- 未接入语音转写的真实录音直接保存为待整理资料，不要求救助者手工转写、分类，也不产生虚构的事实。可用预设口述体验自动整理，或通过一个自由文本输入补充、更正原话。当前存储在本地，尚无后台自动重试任务；接入服务后需要完成转写任务、重试与归档状态同步。
- 宠物 Agent 在领养前后都可引用专属资料库，回答带观察日期和站点来源；未记录的情况明确说明，健康观察不构成诊断。当前为关键词检索和规则分组，尚未接入模型、服务端长期存储和跨设备同步。
- 真正录音可回听并保存在 IndexedDB；语音转写和 Agent 对话仍未接入，需补充文字或使用预设回答。页面集中减少数据提示，设置保留功能接入状态；所有预置人物、动物病例及站点仍为虚构资料。

本轮端到端验证：`npm run test:adopter-ui` 和 `npm run test:rescue-ui`。涵盖直接展示、跨站主页、主动回访回复、浏览器模拟录音、注册中断恢复、画像修改、申请快照、宠物资料保存与问答，以及 360/390/430/953 宽度。下方早期脚本说明中的独立故事入口现位于设置。

## 本地运行

```powershell
node server.mjs
```

打开 `http://localhost:4178`。服务绑定本机所有网卡；同一网络的手机访问还取决于防火墙配置。麦克风录音通常需要 HTTPS 或 localhost，请优先使用已部署的 HTTPS 地址。

```powershell
npm run check
npm test
```

## 手机演示脚本

1. **遇见**：查看橘子的照片、档案及预制短片。
2. **消息**：开启主动招呼，收到橘子的来信。
3. **聊天**：发送“我喜欢狸花，最好安静一点”，点击消息下方的偏好提示确认记录。偏好管理也在“我的”。返回“遇见”，芝麻成为第一推荐。
4. **注册与申请**：从橘子主页点击“我想领养”，先选择示例身份、填写主页昵称，阅读并分别勾选领养公约与保密说明，再填写示例条件提交。注册后也可从“我的”进入身份与公约页面。
5. **切换角色**：右上角滑杆图标 → 救助者。工作台查看申请，依次推进审核、见面和交接。
6. **到家反馈与主页授权**：切回领养人 → 橘子的聊天 → 顶部“记录今天”。拍照、录像或语音记录，确认后弹窗选择“仅发给站点”或“同时展示到个人主页”。关闭弹窗不发送；每条单独授权，旧记录默认不公开。主页不包含私密回访文字、整理结果、站点回复或证件信息；授权的原始媒体可能包含画面或声音中的个人信息，发送前需检查。可以撤下主页展示，站点记录保留。
7. **救助者回复**：切换救助者 → 跟进 → 打开记录，回复并标记处理。
8. **跨天演示与评价**：控制台推进第 1、3、7、30、60…天。所属站点工作台 → 领养者定期评价 → 选择 0–5 星，填写私密事实依据并确认提交。星级、站点与日期同步到领养者主页；无评价与 0 星分开呈现。每 30 天为一个示例周期，历史保留，同一天不重复评价。领养者可以在评价详情登记复核请求；仍为本地演示，未实际通知。
9. **录入新伙伴**：救助者工作台 → 认识新伙伴 → 手机取景拍照或录像 → 下一页语音介绍 → AI/OCR 整理演示 → 确认档案 → 启用 Agent。无相机时可使用手机原生拍摄入口、相册或示例素材。
10. **复盘分支**：控制台 → 演示未回复后的复盘，查看下一位示例用户与新招呼文案。
11. **重置**：控制台 → 重置演示 → 二次确认。
12. **附近**：点击顶部右侧的位置与距离，使用浏览器定位或手动选城市，并选择范围。展示附近的示例救助站与动物，距离按坐标计算直线估算。
13. **随缘遇见**：切换模式，左滑换一位、右滑表示喜欢，或使用按钮操作。支持撤回上次选择、从“喜欢的”回看和重新刷一轮。
14. **救助站主页**：动物卡片上的站名、真实档案、附近站点列表和“我的”均可进入。主页展示站点介绍、待领养动物及对应 Agent 聊天入口。救助者工作台有“我的救助站主页”，控制台可切换三个已开通的示例站。新录入的动物关联当前站点。
15. **站点人工入驻**：注册页或“我的” → 联系平台开通，查看联系、核验、开通流程，登记示例申请后保持“待人工联系”。不会因此开通站点权限，也未发送真实申请；演示控制台切换工作台不代表真实账号授权。
16. **完整示例故事**：从“我的”、消息页或演示控制台进入。阿宁的第一次养猫包含 4 段预置对话、偏好与待见面申请；小禾与米粒包含第 1/2/3/5/7 天回访和待处理问题；阿远与可乐包含第 1/7/14/30/60 天回访、2 次评价和逐条授权的主页日常。进入故事使用独立本地数据，顶部可返回原记录。预置许可、身份与授权仅属于虚构人物。
17. **救助站身份示例**：工作台的“体验有业务数据的救助站工作台”，或故事列表的“暖爪救助站的一天”。含 2 份待审、1 份待见面、1 份待交接申请；2 个已到家家庭、10 条回访，其中 2 条需回复；2 个到期评价、1 份新入站待确认档案、1 条 Agent 复盘。可推进申请、回复、评价和确认草稿。不同领养家庭的主页、资料和到家天数独立对应。支持用 `?story=station-day` 直接进入，返回原记录时移除此参数；刷新不会重复载入情节。

默认目录共 17 只猫狗，分布于杭州与上海的 3 个虚构站点。新增角色包含花色、性格差异、具体照护需求、救助经过、体重、入站时间、观察笔记和 Agent 表达设定。既有用户会自动补齐缺失角色，不覆盖已编辑资料、领养状态、聊天、授权或回访。图库照片不代表与虚构病例或每日回访存在实际关联；同一动物的配图可在故事中复用，不冒充连续实拍。

聊天输入框只保留发消息。顶部根据阶段展示“了解与领养 / 查看进度 / 记录今天”；暂停联系位于右上角“对话设置”。领养后的建议话题转为日常照护。

## 真实操作与模拟能力

真实操作：本地图片上传、保持比例的图片压缩、文本编辑、手机录音及回听、会话输入、记忆更新、规则排序、申请状态、交接、回访及人工回复。

模拟能力：图片文字 OCR、外观及视频识别、语音转写、档案提取、宠物回复、未回复复盘、下一位用户的搭讪。未接入实时 AI 服务。示例口述及用户明确补充的文字参与规则整理，真实录音未被自动转写时标记为待人工听取，不能自动判定动物状态正常。预制视频是程序制作的创意演示，并非实时 AI 生成，也不是动物真实行为记录。

所有人物、救助站、领养档案与流程记录均为示例。动物照片为 Unsplash 素材，与示例档案没有核验关系。界面明确标识示例内容。

注册只接受 DEMO 示例身份，不采集真实证件材料。身份去重仅用于当前浏览器演示，不提供真实实名核验、真实登录、服务端权限、加密身份库或跨设备“一人一号”保证。正式产品需接入身份核验、服务端唯一性约束、最小权限及审计、私密媒体访问控制，才能兑现注册页所描述的平台保密规则。当前“个人主页展示”仅是本地视图，不会发布到公开网络。星级是站点人工记录，不代表平台确认不存在虐待。

结构化数据保存在当前浏览器的 `pawletter.demo.v1` localStorage；确认提交的录像和录音保存在 `pawletter.media.v1` IndexedDB，刷新后仍能回看和回听。未提交的录音、视频只在本次会话中保留。不同手机、不同浏览器和不同域名不共享；原始素材和定位不上传服务器。请勿输入真实敏感资料。重置会同时清除本 Demo 的结构化数据和媒体。

完整故事状态另存于 `pawletter.story.v1`；当前标签页用 `pawletter.story.active` sessionStorage 标识故事模式。进入前保存原数据；返回时恢复原数据。重置故事只重新生成虚构情节，不清空原数据或媒体。切换到另一段故事会替换上一段故事体验状态。原记录模式的“重置演示”仍清除整个 Demo。

定位需用户主动点击授权。所有救助站坐标均为虚构演示数据；默认“杭州”明确标注为演示位置，实际浏览器定位也仅与这些示例站计算距离，不代表真实附近救助站。

## 文件结构

- `dist/index.html`：入口。
- `dist/app.js`：页面、移动端交互、表单和本地状态。
- `dist/domain.js`：记忆、推荐、搭讪、复盘、领养和回访规则。
- `dist/style.css`：移动端界面、桌面展示外框。
- `dist/social.css`：新版墨黑／青柠／电光蓝社交视觉，拍摄和语音流程样式。
- `dist/capture.js`：相机、照片、录像、语音录制及流释放。
- `dist/media-store.js`：已提交素材的 IndexedDB 保存和回放。
- `dist/discovery.js`：演示位置、站点和距离计算。
- `dist/community.js`：示例注册、去重、站点关系、定期评价与公开资料投影。
- `dist/community-ui.js`、`dist/community.css`：注册、公约、入驻、救助站和领养者主页、评价界面及大图刷卡布局。
- `dist/samples.js`、`dist/samples.css`：扩充动物目录、幂等迁移、4 段独立示例故事（含救助站工作台）及故事模式界面。
- `dist/assets/photo-sources.json`：新增图库照片的来源与本地文件对应表。
- `dist/assets/`：照片、图标和预制短片。
- `server.mjs`：本地静态预览。
- `tests/domain.test.mjs`：核心规则测试。
- `tests/ui.mjs`：手机尺寸端到端测试及截图。
- `tests/capture-ui.mjs`：使用模拟摄像头、麦克风和位置验证实际浏览器媒体流程。
- `tests/community.test.mjs`、`tests/community-ui.mjs`：注册公约、0 星、站点评价权限、主页隐私投影、逐条授权、撤下与迁移回归。
- `tests/samples.test.mjs`、`tests/samples-ui.mjs`：17 只动物的关联与迁移，故事数据一致性、独立存储、重置与原操作记录恢复。
- `tests/make-film.mjs`：预制创意短片生成。
- `.openai/hosting.json`：独立 Sites 站点配置。

浏览器测试优先使用 `playwright-core`；当前工作区可复用父目录 `.preview-tools.local` 中的工具。通过 `BROWSER_PATH` 指定 Chrome / Edge 可执行文件。测试使用无界面的浏览器，不修改用户浏览器资料。
